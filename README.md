# Comments — README

**Краткое описание**

Для приложения "explore with me" была выбрана реализация дополнительной функциональности «Комментарии к событиям»

## Содержание

- Реализация фичи «Комментарии к событиям»
- Эндпоинты для операций с комментариями
- SQL: таблица сущности comment


---

## 1. Реализация фичи «Комментарии к событиям»

### Цель

- Позволить пользователям оставлять, редактировать и читать комментарии к событиям.
- Обеспечить модерацию и интеграцию с административной, публичной и приватной логикой системы.

### Основные возможности

- Создание и редактирование комментария к событию (владелец)
- Удаление (владелец/администратор)
- Просмотр комментариев к событию

---

## 2. Эндпоинты для операций с комментариями

### Общие принципы

- Базовый namespace: `/comments`
- Три уровня API: `public`, `admin`, `private`
- Ответы в JSON, статусы HTTP:
    - `200` — OK (GET/PUT/PATCH)
    - `201` — Created (POST)
    - `204` — No Content (DELETE)
    - `400` — Bad Request
    - `404` — Not Found

### Эндпоинты 

#### 1) Public API — чтение (для всех пользователей)

- `GET /event/{eventId}`
    - Описание: получить список комментариев для события
    - Ответ: `200` + массив комментариев

#### 2) Admin API — управление и модерация

- `GET /user/{authorId}`
    - Описание: посмотреть все комментарии пользователя
    - Ответ: `200` + массив комментариев

- `DELETE /{commentId}`
    - Описание: удаление комментария
    - Ответ: `204` 

#### 3) Private API - добавление и редактирование комментария автором комментария

- `GET /{authorId}/{commentId}`
    - Описание: получить конкретный комментарий (в случае запроса от автора комментария)
    - Ответ: `200` + комментарий

- `POST /{authorId}/{eventId}`
    - Описание: создание комментария пользователем (authorId) для мероприятия (eventId).
    - Ответ: `201` + комментарий
  
- `PATCH /{authorId}/{commentId}`
    - Описание: изменение комментария автором комментария (authorId) для мероприятия (eventId).
    - Ответ: `200` + комментарий

- `DELETE /{authorId}/{commentId}`
  - Описание: удаление комментария автором комментария (authorId) для мероприятия (eventId).
  - Ответ: `204`
  
### Пример структуры ответа (comment)

```json
{
  "id": 9,
  "text": "Animi tenetur labore voluptatem et ullam itaque.",
  "eventId": 8,
  "authorId": 8,
  "created": "2025-10-26 10:11:53",
  "updated": "2025-10-26 11:11:53"
}
```

## 3. SQL: таблица сущности comment



```sql
CREATE TABLE IF NOT EXISTS comments (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    text VARCHAR(2000) NOT NULL,
    event_id BIGINT NOT NULL,
    author_id BIGINT NOT NULL,
    created_on TIMESTAMP NOT NULL,
    updated_on TIMESTAMP,
    CONSTRAINT pk_comments PRIMARY KEY (id),
    CONSTRAINT fk_comments_event FOREIGN KEY (event_id) REFERENCES events (id) ON DELETE CASCADE,
    CONSTRAINT fk_comments_author FOREIGN KEY (author_id) REFERENCES users (id) ON DELETE CASCADE
```
